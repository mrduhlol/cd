CD CLI v0.4.0-beta.4 and Android 0.1.8 beta.

Agents now offer paired-device delivery or a download link when handing off APKs and documents. Explicit phone requests with a single pairing send directly; multiple pairings prompt for a destination. Update your CLI and run `cdx agent setup` to refresh installed agent instructions.

Targeted CLI sends run in the background when stdout is captured. The returned PID and private log mean the sender started; only a verified event confirms receipt. Missing and ambiguous pairings fail before launching a sender. `--wait` keeps foreground behavior. A sole paired device can be addressed with `--to phone` even if saved under another alias.

The relay now advertises v2 support, applies the existing IPv6-prefix upgrade limit to v2, rejects noncanonical nonce encodings, and retains replay history through its 128-session cap. Already discarded historical nonces in old relay state cannot be recovered.

Android retains the beta 3 receiving/recovery fixes and advances to version code 9 so it can update the previous beta. The package remains `in.yash0.cd.beta` and requires Android 10+.

Validation includes 83 Android unit tests and lint, 158 JavaScript tests, Go tests and vet, TypeScript, code-security and v2 relay gates, real CLI/browser transfer checks, and zero npm audit vulnerabilities. Physical-phone validation remains outstanding.

This is a beta release. Physical Samsung long-idle/Doze receiving, real configured Firebase delivery and sustained hardware speed improvements remain unverified. The default Android build omits Firebase and is debug-signed. Production signing, distribution and migration are still required before removing beta. Creating a release does not deploy the updated Worker; its server-side fixes require a separate deployment.
