Initial environment failures and limits
- API 35 software emulation had an Android system-server startup watchdog
  restart and repeated launcher/System UI startup ANRs. A CD process also
  failed the platform startup deadline; no app-specific Java/native exception
  was established. API 35 was not accepted as a successful runtime target.
- API 29 with the initial SwiftShader GLES renderer returned black/corrupt
  framebuffer captures, with emulator openColorBuffer errors. The QR pixel
  assertion correctly failed; it was not skipped or weakened.
- API 29 swangle rendered correctly. One System UI startup ANR was dismissed
  before testing; no new platform ANR was observed during the passing run.
- Initial UI harness polling was made asynchronous to handle slow emulator
  transitions. This did not remove any functional assertion.
- No physical ARM64 device, API 35 runtime, or production relay/deployment
  validation is claimed. This report is not a production compatibility or
  security certification.
